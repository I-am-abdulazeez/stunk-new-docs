Middleware lets you intercept every `set()` call on a chunk and transform, validate, or observe the incoming value before it's applied. Stunk ships with built-in middleware and makes it easy to write your own.

---

## How it works

Middleware is passed inside the config object as the second argument to `chunk()`. Each function runs in order on every `set()` call, receives the incoming value, and returns a (possibly transformed) value. If any middleware returns `undefined`, the chain stops and no update is applied.

```ts
import { chunk } from "stunk";
import { logger, nonNegativeValidator } from "stunk/middleware";

const count = chunk(0, {
  middleware: [logger(), nonNegativeValidator],
});

count.set(5); // logs "Setting value: 5" → applies
count.set(-1); // throws "Value must be non-negative!"
```

Middleware runs **before** the value is stored. If any middleware throws, the chunk value is not updated.

---

## Built-in middleware

### `logger()`

Logs every `set()` call to the console. Called as a factory — `logger()` not `logger`.

```ts
import { chunk } from "stunk";
import { logger } from "stunk/middleware";

const count = chunk(0, { middleware: [logger()] });

count.set(10); // console: "Setting value: 10"
```

### `nonNegativeValidator`

Throws if the incoming value is negative. Used directly — not a factory.

```ts
import { chunk } from "stunk";
import { nonNegativeValidator } from "stunk/middleware";

const score = chunk(0, { middleware: [nonNegativeValidator] });

score.set(100); // ✅
score.set(-5); // ❌ throws "Value must be non-negative!"
```

<Callout type="info">
  `logger` and `nonNegativeValidator` are **chunk middleware** — passed inside
  `chunk()` config. `history` and `persist` are different — they wrap a chunk
  after creation. See their dedicated pages for details.
</Callout>

## Writing your own middleware

A middleware is a function that receives a value and returns a value:

```ts
import type { Middleware } from "stunk";

const clamp =
  (min: number, max: number): Middleware<number> =>
  (value) =>
    Math.min(Math.max(value, min), max);

const volume = chunk(50, { middleware: [clamp(0, 100)] });

volume.set(150); // clamped to 100
volume.set(-10); // clamped to 0
```

Use the named format for better dev-mode error messages:

```ts
const count = chunk(0, {
  middleware: [
    { name: "logger", fn: logger() },
    { name: "clamp", fn: clamp(0, 100) },
  ],
});
```

### Stopping the chain

Return `undefined` to stop the chain and skip the update entirely:

```ts
const noZero: Middleware<number> = (value) => {
  if (value === 0) return undefined; // skip
  return value;
};

const count = chunk(1, { middleware: [noZero] });
count.set(0); // no update, value stays 1
```

### Transforming values

Middleware can return a modified value:

```ts
const uppercase: Middleware<string> = (value) => value.toUpperCase();

const name = chunk("fola", { middleware: [uppercase] });
name.set("tunde"); // stored as "TUNDE"
```

### Async middleware

Middleware is synchronous by design. For async side effects use `subscribe()` instead:

```ts
count.subscribe(async (value) => {
  await fetch("/api/log", { method: "POST", body: JSON.stringify({ value }) });
});
```

---

## Execution order

Middleware runs left to right. Each receives the output of the previous:

```ts
const count = chunk(0, {
  middleware: [
    middlewareA, // runs first
    middlewareB, // receives output of A
    middlewareC, // receives output of B
  ],
});
```

If any middleware throws, the chain stops and the chunk is not updated.
