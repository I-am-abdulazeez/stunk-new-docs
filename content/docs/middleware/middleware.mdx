Middleware lets you intercept every `set()` call on a chunk and transform, validate, or observe the incoming value before it's applied. Stunk ships with built-in middleware and makes it easy to write your own.

---

## How it works

Middleware is passed as the second argument to `chunk()` — an array of functions that run in order on every `set()` call. Each middleware receives the incoming value and returns a (possibly transformed) value. If a middleware returns `undefined`, the chain stops and no update is applied.

```ts
import { chunk } from "stunk";
import { logger, nonNegativeValidator } from "stunk/middleware";

const count = chunk(0, [logger, nonNegativeValidator]);

count.set(5); // logs "Setting value: 5" → valid, applies
count.set(-1); // logs "Setting value: -1" → throws "Value must be non-negative!"
```

Middleware runs **before** the value is stored. If any middleware throws, the chunk value is not updated.

---

## Built-in middleware

### `logger`

Logs every `set()` call to the console. Useful during development to trace state changes.

```ts
import { chunk } from "stunk";
import { logger } from "stunk/middleware";

const count = chunk(0, [logger]);

count.set(10); // console: "Setting value: 10"
```

### `nonNegativeValidator`

Throws if the incoming value is negative. Only works on `Chunk<number>`.

```ts
import { chunk } from "stunk";
import { nonNegativeValidator } from "stunk/middleware";

const score = chunk(0, [nonNegativeValidator]);

score.set(100); // ✅
score.set(-5); // ❌ throws "Value must be non-negative!"
```

<Callout type="info">
  `logger` and `nonNegativeValidator` are **chunk middleware** — they're passed
  directly to `chunk()`. `withHistory` and `withPersistence` are different —
  they wrap a chunk after creation. See their dedicated pages for details.
</Callout>

## Writing your own middleware

A middleware is just a function that receives a value and returns a value:

```ts
import { Middleware } from "stunk";

const clamp =
  (min: number, max: number): Middleware<number> =>
  (value) => {
    return Math.min(Math.max(value, min), max);
  };

const volume = chunk(50, [clamp(0, 100)]);

volume.set(150); // clamped to 100
volume.set(-10); // clamped to 0
```

You can also use the named middleware format for better error messages:

```ts
const count = chunk(0, [
  { name: "logger", fn: logger },
  { name: "clamp", fn: clamp(0, 100) },
]);
```

### Stopping the chain

Return `undefined` to stop the middleware chain and skip the update entirely:

```ts
const noZero: Middleware<number> = (value) => {
  if (value === 0) return undefined; // skip the update
  return value;
};

const count = chunk(1, [noZero]);
count.set(0); // no update, value stays 1
```

### Transforming values

Middleware can return a modified value — not just validate:

```ts
const uppercase: Middleware<string> = (value) => value.toUpperCase();

const name = chunk("fola", [uppercase]);
name.set("tunde"); // stored as "TUNDE"
```

### Async middleware

Middleware is synchronous by design. For async side effects (e.g. logging to a server), use `subscribe()` instead:

```ts
count.subscribe(async (value) => {
  await fetch("/api/log", { method: "POST", body: JSON.stringify({ value }) });
});
```

---

## Middleware execution order

Middleware runs left to right. Each receives the output of the previous:

```ts
const count = chunk(0, [
  middlewareA, // runs first
  middlewareB, // receives output of A
  middlewareC, // receives output of B
]);
```

If any middleware throws, the chain stops and the chunk is not updated.
